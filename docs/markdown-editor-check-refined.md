## 一、段落式显示

**原稿**：显示样式有别于传统文本编辑器分行设计；shift+enter 不分段仅换行，enter 进行分段；段落之间不以行为分界线（至少在显示上不行），且光标不能放置在段落之间，段落距离略大于段内行间距在视觉上区分段落。

**问题**：原稿把「现状」和「目标」写在同一句里，且没有验收口径。

**调优后的规格（R1.1–R1.5）**

- R1.1 分段语义：Enter = 新段落（源文件段与段之间空一行）；Shift+Enter = 段内软换行（源文件单换行）。**源文件格式不改**（导出/预览/知识抽取都按「空行 = 段落」的 Markdown 口径工作）。
- R1.2 显示上不出现整行空行：段落分隔不能渲染成「一整行空白」再靠它表达段距。
- R1.3 光标不停在段落分隔处：常态下（点击/方向键）分隔处不是一行字符，光标落不到那里。
- R1.4 段距略大于行距：约 1.25–1.45 倍（不是 2 倍）。
- R1.5 不回归：跨段选择、上下键、Backspace 合段、撤销重做、导出/预览不受影响。

**技术与落地**

- 默认的 Compose 编辑器是「整篇一个 text field」，行高整篇统一（26sp）。2026-11-12 用 `MultiParagraph` 实测复核：逐行 `ParagraphStyle` 会多出重复行、零宽空格压不下行高 → **R1.2–R1.4 无法同时成立**，保留现状（空行 = 2 倍段距），这是已知限制。
- 块级 DOM 的 Tiptap 路线本来就满足 R1.2–R1.4（空行不在文档里、段距由 CSS margin 控制：24px 行高 + 10px 段落间距 ≈ 1.42 倍）。2026-11-12 起它是设置页里的可选项：**设置 → 编辑器 → 段落式（WebView 实验）**，即时生效并写进 `ui.json`；`TRELLIS_EDITOR` 环境变量仍可强制。
- 默认不切到段落式：那条实验路径的代码高亮/表格/公式渲染、AI 补全、自定义键位还没对齐，切默认是功能回退（设置页就地注明）。
- 2026-11-14 修：切到段落式后曾出现「窗口还在、整页点不动」——JavaFX toolkit 初始化失败时 `JFXPanel` 会在 EDT 的 `SecondaryLoop` 里死等。现在启动挪到后台线程（20s 超时）、`javafx.cachedir` 指到系统临时目录，失败就回退 Compose 编辑器并在正文上方说明原因。

**验收**：设置里切「段落式」→ 写三段文字：段落之间无空行、段距约 1.4 倍；切回「单文本」恢复现状。Compose 编辑器下段距仍是 2 倍（已知限制）。

## 二、Tab / Shift+Tab

**原稿**：「Table 没有进行深度定制，table 在非代码块中应起到『抬高』层级的作用…而在代码块中，tab 和 shift+tab 都要能够将所处行或者所有选中行进行空格填充。」

**问题**：`Table` 是 `Tab` 的笔误——示例给的是有序列表层级（`1.` 缩进一级渲染成 `1.1`），原稿并没有在说 Markdown 表格。

**调优后的规格（R2.1–R2.4）**

- R2.1 列表层级：光标/选区在列表（无序、有序、任务）或引用行上时，Tab = 缩进一级（2 空格），Shift+Tab = 撤销一级；多行选区逐行处理，空行跳过；缩进不重写有序编号（编号由渲染按层级显示）。
- R2.2 代码块缩进：光标在围栏代码块（围栏行或内容行）时，Tab = 当前行或所有选中行行首加 4 空格；Shift+Tab = 行首删掉最多 4 个空格（Tab 字符也算一个单位）。代码块里的空行也补缩进；正文/列表里的空行跳过。
- R2.3 普通行：Tab = 行首加 2 空格；Shift+Tab = 行首删掉最多 2 个空格。
- R2.4 按键优先级：AI 补全的 Tab 接受手势最优先（行尾有 `。。。` 时），其次是 `[[` 概念补全、斜杠菜单的 Tab 认领，最后才轮到缩进；菜单没开且没有补全建议时 Tab 一定做缩进。

**验收**：列表行 Tab 后缩进两格、Shift+Tab 复原；代码块里选中多行 Tab，每行加 4 空格、行数不变（空行也缩进）；正文/列表以外的 Tab 不再「按了没反应」。

## 三、快捷键补全 + 设置里自定义

**原稿**：「补全目前所有菜单功能的快捷键并可以在设置中自定义。」

**问题**：菜单 17 个命令只绑了 14 个（缺任务清单/代码块/图片）；键位写死在代码里，没有设置入口。

**调优后的规格（R3.1–R3.5）**

- R3.1 覆盖完整：17 个命令全部有默认键位。沿用旧 14 条：粗体 `Ctrl/Cmd+B`、斜体 `I`、链接 `K`、删除线 `Shift+X`、行内代码 `Shift+C`、一级/二级/三级标题 `1/2/3`、正文 `0`、无序/有序列表 `Shift+L/O`、引用 `Shift+Q`、分割线 `Shift+R`、表格 `Shift+T`；新增：任务清单 `Shift+K`、代码块 `Shift+E`、图片 `Shift+I`。
- R3.2 可自定义：设置页「Markdown 快捷键」逐条显示当前键帽；点「改键」进入捕获态（按任意组合键生效、Esc 取消），可「解绑」、单条「恢复」、全部恢复默认。
- R3.3 校验：只接受 `Ctrl/Cmd`（按平台）、`Shift`、`Alt` + 字母/数字/少量符号；同一个键不能绑两个命令（拒绝并提示占用者）；`Ctrl/Cmd+S/N//Q` 是页面/窗口快捷键，不能绑给命令；非法键位忽略并回退默认。
- R3.4 生效面：编辑器按键分发、页头「菜单」快捷键清单读同一份生效键位，改完立刻变。
- R3.5 持久化：覆盖存 `<home>/markdown.json`（`{"bindings": {...}}`，空串 = 解绑），只存与默认不同的项；坏文件/未知命令/非法键位一律回退默认，不挡启动；清除数据时保留。

**验收**：设置页把粗体改成 `Ctrl/Cmd+Shift+B` → 回编辑器按 `Cmd+B` 不插入粗体、`Cmd+Shift+B` 插入；页头「菜单」显示新键位；重启后仍然生效；「全部恢复默认」回到上表。
