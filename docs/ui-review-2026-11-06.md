## 0 摘要

**一句话结论**：页面骨架大多站得住，难看的根源在底层的「样式词汇」。默认主题 Bento 把一套英文看板样片（等宽大写小标、窄体数字、青柠 + 纯黑、3dp 硬边）硬套在中文学习工具上，又只落地了一半：卡片实际是 12dp 圆角，控件 6dp，主题声明的却是 3dp。等宽字体没有中文字形，于是中文落回系统字体，数字和英文仍是等宽，整屏混排发碎。全应用 266 处文字挤在 `labelSmall`（11sp）上，层级被压平。所以不需要推倒重写。

**最该动的三件事**

1. **重建 token 层**：语义色、字号阶梯、间距、圆角、密度。顺手修掉三个确定缺陷：密度方向反了、设置页里改不了深浅色和字号、边框与链接对比度不达标。
2. **合并任务页与计划页的「今天」**：现在待办里混着两种行模型，可勾选的任务和不可勾选的计划节点挤在同一张卡里。
3. **重做知识网络的初始视图与浮层**：一进页面就是一屏读不出字的纹理；弹卡和 AI 建议面板叠在画布上互相遮挡。

**推荐**：方案 A（渐进式），并把方案 B 的「目标设计系统」作为 A 的第 0 批先做，估 19–27 人日。B 的整体重构（45–65 人日）边际收益主要集中在任务/计划两页，不值得全量推倒。

## 3 逐页诊断

评分口径：1 = 明显缺陷，3 = 可接受但有明显改进空间，5 = 可作样板。

### 3.1 导航壳（左栏 + 内容列）

**现状**：88dp 左栏，图标是 8×8 像素点阵画的 16dp 图形（`PixelIcons.kt:21-127`）。内容列限宽 1120dp 居中；对话和知识库两页特殊，贴边铺满（`AppScreen.kt:102-114`）。

**保留**：

- 像素图标是全应用唯一有辨识度、又不像模板的元素，值得留作品牌资产。
- 「插件 / 诊断页停留时点亮『设置』」（`AppScreen.kt:181-190`）这一处理是对的。

**问题**：

- **P2 / 确定**：左栏上下各悬空 16dp。外层 `Row` 的 `padding(vertical = 16.dp)` 也作用在左栏上（`AppScreen.kt:96`），S1–S12 里左栏都是一条浮着的白带，没有贴住窗口上下边。
- **P2 / 确定**：左栏底色 `surface` #FFFDF7 和页面 `background` #F7F5EE 几乎分不出来，1dp 分隔线用的 `outlineVariant` 对 surface 只有 1.32:1。左栏和内容区之间只靠一道肉眼难辨的线分开。
- **P1 / 确定**：「顶栏」形态用的是 M3 `TabRow`，纯文字、没有图标（`AppScreen.kt:194-231`）；「左栏」是自绘的（`:241-322`）。同一个偏好对应两套视觉语言。
- **P1 / 确定**：选中态是青柠 `primaryContainer` #D6F24B 铺底，对背景只有 **1.16:1**，低于 WCAG 1.4.11 要求的非文本 3:1。选中只能靠色相分辨，灰度或色弱下看不出来。
- **P2 / 确定**：主窗口没设 `minimumSize`，只给了退路尺寸 520×420（`Main.kt:44-54`），可以把窗口拖到任意小。
- **P2 / 确定**：启动页和失败页用的是裸 `MaterialTheme {}`，即 M3 默认紫（`Main.kt:177-187`），启动瞬间会闪一下别的品牌色。

| 视觉层级 | 信息架构 | 一致性 | 状态完备 | 实现健康度 | 窄窗/移动 |
|---|---|---|---|---|---|
| 3：图标加文字清楚，选中只靠色相 | 4：六页够用，二级页收进设置是对的 | 2：顶栏和左栏两套语言 | 3：有未读红点 | 3：自绘但取了语义色 | 2：无最小尺寸、无断点 |

### 3.2 任务页（插件内核渲染）

**现状**：`PlanUiPlugin` 把「今日盘点 Header」和「待办 TaskBoard」两个宿主 composable 注册成 `slot.home.header` / `slot.home.section` 的贡献（`PlanUiPlugin.kt:51-67`）。外壳是 `BentoCard`（`AppScreen.kt:398-453`）。

**保留**：

- 插件化托管本身。agent 能排版和改卡片样式，是这个产品的差异点。
- 44dp 勾选热区配 20dp 视觉框（`AppScreen.kt:828-836`）。
- 逾期用「红点 + 红字」双编码（`:869-877`）。
- 自然语言日期识别后变成 chip（`:925-927`）。
- 删除后 5 秒可撤销、不弹确认框（`:546-566`）。
- 大字号下 KPI 自动改成 2×2（`:733-748`）。
- 这些交互细节都是对的，重构时必须原样保留。

**问题**：

- **P1 / 确定｜信息架构**：同一张「待办」卡里有两种行模型。
  - 任务行（`TaskRow`，`:803-896`）有勾选框；计划节点行（`PlanNodeRowView`，`:623-672`）只有灰点、不能勾选（注释写的是「节点在待办里不可勾，勾选走计划页」，`:617`）。
  - S1 里「完成论文初稿」带勾选框，下面五条「课时 7 网络安全 / 4.1.x Linux…」只有小圆点。用户会把它们当成同一种待办，点了却没有反应。
  - 这不是样式问题，是任务和计划两套模型在界面上没有统一。
- **P1 / 确定｜一致性**：操作入口出现的条件不一样。任务行的 ⏱ 只在悬停时出现（`:890-894`）；计划节点行的 ⏱ 一直显示（`:661`）。S1 右侧只有节点行带着 ⏱ 和「逾期 1 天」。日期标签的位置也不一样：任务在标题下方（`:867-878`），节点在行尾（`:662-670`）。
- **P1 / 确定｜字体**：英文等宽大写小标「DAILY SNAPSHOT」「TASKS」「TREND」（`:714, :461, :382`），以及 `GroupLabel` 对中文调用 `uppercase()`（`:685`）。对中文 uppercase 不起作用，只剩等宽字体，而 IBM Plex Mono 没有中文字形，中文回落到系统字体。
  - S1 里「逾期 1」「学习计划 5」「约 24 分钟」「第4章 33 分钟」的数字、空格和中文宽度不一，节奏发碎。
  - 这是 frontend-design 里点名的模板痕迹（英文 eyebrow 小标），放在中文学习工具上没有信息量。
- **P1 / 确定｜版面**：内容列限宽 1120dp（`AppScreen.kt:109`），输入行另外限宽 620dp（`:941`）。S1 里输入框只占卡片宽度一半，右边空着；整页下半屏（y > 710pt）完全空白。
  - 首页是「今天该做什么」的主屏，却只有一条窄列表，没有利用横向空间做「今天 / 本周进度 / 计时」的并列。
- **P2 / 确定｜视觉**：KPI 数字是 `displaySmall` + Bold（`:781-783`），Bento 下是 Barlow Condensed。窄体只打包了 400/600 两档（见 §4.1），Bold 会被合成或回退。单位「条」用 11sp 的 labelSmall 贴在 36sp 数字旁边，两者大小差约 3.3 倍，单位几乎看不见。
- **P2 / 推测｜内容**：S1 里两条「课时7网络安全 · 未分章 12 分钟」完全相同、无法区分。可能是同一节点的两次 occurrence，界面没有提供区分信息，比如日期。
- **P2 / 确定**：完成率 Pill 用 `primaryContainer` 底 + `accentText` 字（`:725-729`），连续天数 Pill 用 `data` 色（`:720-724`）。两个并排的徽章各用一套配色，是 Bento 的「岗位色」体系（`BentoThemePlugin.kt:111`）在一行里同时露出三种语义色。

|---|---|---|---|---|---|
| 3：KPI 醒目，列表层级扁平 | 2：两种行模型混排 | 2：⏱ 和日期位置不一 | 4：空态、撤销、大字号分支都有 | 3：插件化干净，样式散落 | 3：KPI 有字号分支，输入行定宽 |

### 3.3 计划页

**现状**：232dp 计划列表 + 主列，主列从上到下是周卡带（LazyRow，196×184dp 卡）、七天条、当天安排、AI 自动完成卡（`PlanScreen.kt:109-148, 483-547, 607-691, 832-1009`）。重排抽屉宽 296dp，打开时把内容推开（`:102-112`）。

**保留**：

- 「周 → 天 → 当天条目」的下钻结构是对的。
- 拖拽到天格时的 1.06 倍缩放反馈和不可放置格降透明度（`:859-893`）。
- 抽屉打开时让开内容、不遮挡周五到周日的格子（`:101-112`）。
- 待安排合成一张半宽卡，和 plan-page.md 一致（`:555-604`）。

**问题**：

- **P1 / 确定｜页头**：页面没有标题。
  - 左列顶上的「计划」是 11sp 灰色 labelSmall（`:156-160`），主列顶上是「总览」11sp + 「按周排」titleMedium（`:486-492`）。两者不在同一基线：S2 里左「计划」在 y≈24pt，右「总览 按周排」在 y≈40pt。
  - 「1 周」「重排 · 2」「计划设置」三个右上动作分别用 labelMedium、labelLarge、labelLarge（`:498-516`），「重排 · 2」的「2」是什么，没有说明。
- **P1 / 确定｜组件 bug**：AI 自动完成卡的标题行里放了 M3 `TextButton`「解除屏蔽（1）」（`:281-287`）。TextButton 最小高度约 40–48dp，把标题行撑高，标题小字被垂直居中。S2 里这张卡顶部有一段异常空白，标题像是掉下去了。

- **P1 / 确定｜选中态**：周卡选中时是 2dp 的 `primary` 描边（`:610-627`），Bento 的 primary 是 #141414 纯黑，于是选中 = 粗黑框。天格选中是青柠底（`:875`），列表选中也是青柠底（`:192`）。同一页里选中有两种表达。

- **P2 / 确定**：周卡高度固定 184dp（`:624`）。章节名有 maxLines=1，单元最多 3 条且有省略（`:643-659`），截断是安全的，但大字号下会挤压底部的日期行 [未验证：fontScale 1.25 + compact]。
- **P2 / 确定**：周卡带横向靠「按住拖动」滚动（`:523-529`），没有滚动条也没有左右按钮。周数多了以后发现不了还能横滑 [未验证]。

## 4 横向诊断

### 4.1 设计系统：token 只落地了一半

**颜色角色**：分三层，彼此不协调。

- M3 `ColorScheme`（`AppTheme.kt:76`）。
- `ExtraColors` 10 个岗位色（`ui-kernel/.../ExtraColors.kt:22-33`）。
- 散落的写死色：`desktop/` 目录下除主题文件外有 41 处 `Color(0x`，ui-kernel 还有 2 处 #2E7D32（`SlotArea.kt:421`）。

问题出在 Bento 的角色分配。`primary` 是纯黑 #141414，`primaryContainer` 是青柠（`BentoThemePlugin.kt:56-58`），于是：

- 「主按钮」「选中周卡」「开关」「日视图」都是黑的；
- 「选中导航」「选中列表行」「用户气泡」「完成率」都是青柠。

一套品牌色被拆成两种语义，再加上靛 data、橄榄 accentText、紫 steward、琥珀 running，**一屏最多同时出现 6 种强调色**（S4 一屏里就有青柠、紫、黑、橄榄四种）。

**对比度**：

- 正文、次级正文、主色这几对，在所有配色方案里都过了 AA。`Palette.kt` 的 OKLCH 推导加上「正文 ≥7:1、其余 ≥4.5:1」的门槛（`Palette.kt:148-161`），以及 `ThemePacks.kt` 的校验（`:49-63`），**这套对比度门槛是现有代码里最值得保留的资产**。
- 但门槛只覆盖文字对，不管边框和状态：
  - `outlineVariant` 对 surface 在全部 12 套方案里都只有 1.32–1.76:1，卡片边、分隔线、左栏线都靠它。
  - Bento 浅色的 `outline` 2.06:1。
  - 禁用的 ChromeButton 文字 2.2–2.5:1（`Chrome.kt:110`）。
  - 链接 #2E5AAC 在 Bento 深色上 2.60:1（`MarkdownText.kt:657`）。
  - Bento 深色的 danger / warning container 是推导出来的，对 surface 只有 1.05–1.09:1，等于看不见。

**字体**：

- 打包了 Barlow Condensed 400/600 和 IBM Plex Mono 400/600，都没有中文字形。
- Bento 把 `labelFamily` 设成 mono、`displayFamily` 设成 condensed（`BentoThemePlugin.kt:104-109`）。
- 结果：
  - 所有 `labelSmall` / `labelMedium` / `labelLarge`（共 324 处）都在中西混排中回退。
  - 代码里用了 Bold 18 次、Medium 14 次、Black 1 次，但打包的字体只有 400/600 两档，这些字重会合成或就近取。
- **字号阶梯**：`labelSmall`（11sp）用了 266 次，是第二名 `bodySmall`（60 次）的 4 倍多。写死的 sp 有 15 种（9 / 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 15 / 15.5 / 16 / 26 / 27.6 / 34 / 64 / 68）。层级靠「等宽 vs 非等宽」和「灰色透明度」来区分；灰色透明度也没有收敛，`onSurfaceVariant.copy(alpha = …)` 有 12 种取值（0.26–0.85）。
  - alpha 0.6 时对 surface 3.14:1，0.5 时 2.51:1，**这些都是小字，都不达 AA**。

**间距与圆角**：

- dp 字面量 982 处、66 种取值，3 / 5 / 7 / 9 / 13 这类奇数都有，没有 4 或 8 的格子。
- 圆角字面量有 12 种取值。
- `MaterialTheme.shapes` 在 `desktop/` 里被引用 **0 次**。
- 实际圆角是这样分配的：
  - 主题声明 cardRadius = 3；
  - 控件 `ControlShape` 写死 6dp（`Chrome.kt:55`）；
  - 插件卡用 `UiPrefs.radius`，默认 **12**（`UiPrefs.kt:46`，`AppTheme.kt:56-65`）；
  - 管家卡 12；导航项 4；列表行 4 或 6。
- 所以 S1、S2 的卡片明显是 12dp 大圆角，配上 3dp 方角的小 Pill，**样片的「硬边」气质在默认状态下根本没出现**。作者觉得「不对劲」，很大一部分来自这里：主题说一套、组件做另一套。

**密度方向反了（P1 / 确定）**：

- `densityScale` 的定义是 compact = 1.12、relaxed = 0.9（`UiPrefs.kt:134-138`），并且乘在 `Density.density` 上（`AppTheme.kt:52-55`）。
- density 越大，每个 dp 占的像素越多，所有东西都变大。所以「紧凑」实际放大 12%，「宽松」实际缩小 10%，注释（`UiPrefs.kt:133`）写反了。
- 而且这是整体缩放，dp 和 sp 同比例变化，并不是「密度」：行高和留白相对于文字没有任何变化。

**主题包、深浅色、变体的一致性**：

- 桌面 Bento（纸底 + 黑 + 青柠 + 3/6/12dp）和手机 `PhoneTheme`（纸底 + 松绿 #3E6B56 + 陶土 + 6/10/12dp，`mobile/PhoneTheme.kt:37-51, :179-181`）是**两套品牌**。
- 手机端注释说两者「共用一份性格」（`PhoneTheme.kt:5-13`），实际上主色完全不同。
- 有一个值得注意的证据：H2 的手机截图比桌面截图安静、耐看。原因是它用了一个低饱和主色，并且 label 层次分明。

### 4.3 状态

- **做得好**：对话页的运行 / 失败 / 中断 / 撤销。
- **基本具备**：任务空态和撤销、计划空态。

这一节只列硬缺陷，品味问题不在此列。

1. 选中态只靠青柠底，1.16:1。
2. 卡片和分隔线 1.3–1.8:1。这是装饰性元素，可以放宽，但要求卡片可点时就不行。
3. 小字灰色透明度低于 4.5:1。
4. 设置页节标题 4.21:1。
5. 自绘单选未选中态 1.23:1。
6. 写死的状态色在深色下 3.0–3.4:1。
7. 按钮没有焦点环。
8. 字号调节入口只存在于 AI 工具里。
9. 中文伪斜体，影响阅读障碍用户。

**偏好项（不算缺陷）**：青柠气泡过亮；等宽小标的风格。

### 4.5 插件 UI 词汇（UiNode）

**能表达**：

- 布局：Column / Row / Grid（1–4 栏）/ Section。
- 文本：样式、色调、字号、字重、字族。
- 图表：Bars / Sparkline / Columns / Area / Ring / DotMatrix / HeatStrip / Table / Stat。
- 交互：Badge / Progress / Button / Input / Stepper / Notice。
- 其他：Image / Icon（emoji）（`kernel/.../slot/UiNode.kt`）。

**不能表达**，这决定了插件卡片的视觉上限：

- **没有间距 token**：`gap` 是任意整数（`DynamicSlotView.kt:128-148`），插件作者可以写 7 或 13。
- **色调不全**：没有 Warning；Success 映射到 `tertiary`（`:938`），而宿主的 `SlotTone.SUCCESS` 是写死的绿，两边不一致。
- **组件和宿主不一致**：Button / Input 渲染成 M3 `OutlinedButton` / `OutlinedTextField`（`:792, :830-852`）。这正是 `Chrome.kt:40-48` 明确拒绝的 56dp M3 控件，**插件卡上的按钮和宿主按钮长得不一样**。
- **缺基础交互件**：没有列表行、开关、chip、tabs、链接、tooltip。
- **图标只能用 emoji**。
- **文本**：没有 maxLines，也没有省略。
- **卡片内容**：`TemplateSlot` 卡片的 body 项之间间距为 0（`SlotArea.kt:252`）。

结论：只改宿主样式，插件卡会立刻显得格格不入。**新的设计系统必须同时扩展 UiNode 词汇**，例如 gap 改成枚举、补 Warning、Button 按变体走 Chrome 组件，否则插件化就会拉低整体视觉。

### 4.6 KMP 共享与窄窗约束

- 桌面全应用只有对话页用了 `BoxWithConstraints`（`ChatScreen.kt:404`），**其余页面没有任何宽度断点**。
- 定宽元素：计划列表 232、重排抽屉 296、执行清单 296、ListSidebar 220–360、知识库右栏 180–420、AI 建议面板 392、周卡 196。
- 以 1000px 窗口推算知识库：88（左栏）+ 264（列表）+ 8（分隔条）+ 编辑器 + 12 + 240（右栏）+ 页内留白，编辑器只剩约 330dp，每行约 20 个汉字，加上 34dp gutter 后更窄 [未验证：1000×700 截图]。
- 手机端基本自建一套页面（`mobile/` 5415 行），共享的只有 `SlotArea`（插件卡）、`MarkdownText`、`StewardProposalCard`，**以及整页 `ActivityScreen`**（`PhoneApp.kt:220`）。
  - 手机端会把桌面活动页的「五按钮顶栏 + 宽卡片」原样放到 390pt 宽里，这是共享 UI 在手机宽度下最可能崩的一处 [未验证]。
  - `StewardProposalCard` 的紫色和 12dp 也随之进入手机端，与 PhoneTheme 的松绿冲突。

## 6 方案 B：整体重构

### 6.1 设计方向

Trellis 是给学生长时间使用的学习工具：读笔记、排计划、看进度，一坐几个小时。目标气质是**「一张安静的书桌，加一支荧光笔」**：

- 冷灰纸底 + 墨色正文，长时间看不累。
- 一个低饱和的「黑板绿」作为唯一品牌色，用于操作和选中。
- 一个「荧光黄」只用来标记 AI 和概念高亮。这是学习场景特有的语义：AI 替你画的重点，就是荧光笔的痕迹。

这个方向刻意回避三种常见路线：AI 界面常见的奶油纸 + 衬线 + 陶土色；暗底 + 单一酸性绿；SaaS 式的同质圆角卡片堆叠。它也与手机端已经验证过的松绿（`PhoneTheme.kt:42` #3E6B56）同色系，**双端可以收敛成一套品牌**。

### 6.2 目标设计系统

数值汇总见 §8.1。

- **颜色角色**（浅 / 深各一套）：
  - 底：bg / surface / sunken。
  - 文字：ink / ink2 / ink3。
  - 线：rule（装饰）/ ruleStrong（可交互边界，≥3:1）。
  - 品牌：accent / onAccent / accentSoft / onAccentSoft。
  - 标记：mark / onMark（AI、概念）。
  - 状态：danger / warn / ok / info。
  - 每对都按 §8.1 的表计算过：正文 ≥7:1，ink3 和状态色 ≥4.5:1，ruleStrong ≥3:1。
- **字体**：
  - UI 和正文用系统中文字体栈：macOS PingFang SC、Windows Microsoft YaHei UI、Linux / Android Noto Sans CJK SC，只用 400 / 500 / 600 三档。
  - 数字用 tabular figures。
  - 等宽 IBM Plex Mono 只用于代码块、过程详情和 diff。
  - Barlow Condensed 退役。
- **字号阶梯（sp / 行高）**：
  - 界面：12/18（meta）· 13/20（control）· 14/22（body）· 16/24（title）· 20/28（page）· 28/34（stat）。
  - 阅读：16/28，正文最宽 36em。
- **间距**：4 · 8 · 12 · 16 · 24 · 32 · 48；页边距 24（中档 16）；卡内边距 16；列表行左右 12。
- **圆角**：4（控件、chip、行）· 8（卡片、弹卡）· 12（对话框、抽屉）；只有计数徽章用全圆。不用硬阴影。
- **层级阴影**：e0 无；e1 只用 1px ruleStrong；e2（弹卡、菜单）用 `0 4 16 / ink 12%`，深色改成「surface 提亮 4% + rule 描边」，不靠阴影。
- **密度**：compact / standard / comfortable 对应列表行高 32 / 40 / 48dp、卡内边距 12 / 16 / 20、控件高 32 / 36 / 40；字号不随密度变化，字号只受字号偏好控制。

## 7 推荐与决策点

**推荐 A**，以 B 的设计系统（§6.2 和 §8.1）作为 A0 的目标值。理由：

- **小改即可的页面**：
  - 对话、设置、诊断、插件：骨架是对的，问题全在 token、组件和元操作，A0–A2 加 A5 就能到 4 分。
  - 活动：时间轴是样板，只需要改头部和配色。
  - 知识库·笔记：编辑器手感好，换 token、去掉伪斜体、解决贴边。
- **结构有问题、需要重做局部的页面**：任务页（行模型）、管家卡、知识网络初始视图。这些在 A3、A4、A5 里按局部重写处理，不必整体推倒。
- **已经没救的部分**：没有哪一页需要整页推倒。真正「没救」的是**两样东西**：Bento 作为默认主题的英文看板气质，以及「主题、控件、插件卡」三套圆角并存的现状。这两样必须废掉，而 A0 就能做到。
- **重构的边际收益**：B 比 A 多出约 25–40 人日，换来的是任务页两栏化、设置页双栏、手机端统一品牌这三项。只有手机端统一品牌是 A 做不到的；它可以在 A 完成后作为独立的第 7 批（≈ B6，4–6 人日）追加，不必现在押注整体重构。

**评分维度取舍**：覆盖与证据优先于方案细节。插件、诊断、计时器三页没有截图，评分标了「代码推断」，没有为凑满证据去猜测视觉。

**需要你拍板的地方**：

1. **默认主题**：Bento 退为可选主题，默认改成 §8.1 的「书桌 + 荧光笔」，还是保留 Bento 但修正它（去等宽小标、圆角统一为 4、青柠只用作 mark）？后者成本低约 1 人日，但「英文看板」的气质仍在。
2. **今天页的节点勾选**：在任务页勾选计划节点，是否等同于在计划页完成这个 occurrence？如果否，节点就不该出现在待办里，应该单独成为一栏「今天的学习」。
3. **知识网络首屏**：默认停在「根分类 + 一层」（推荐），还是记住上次相机位置？
4. **AI 标记语义**：「AI」标签是标记「AI 建议、未确认」（推荐），还是标记「AI 生成」？前者在用户确认后消失。
5. **UiNode 的 gap 迁移**：旧插件的任意整数，四舍五入到最近的枚举值（推荐），还是保留 Int 但限制在 token 集合内？
